# v1.3.5 — Startup Recovery

A loading overlay depended on scene-wide graphics readiness rather than the actual playable map. A map-loading rejection could also leave its error and retry controls behind that overlay. Startup now reports map decode/build stages and dismisses the overlay once the map and showroom are ready. Map features decode in batches with UI yields.

A small recovery script runs before the engine and map scripts. It displays early script/initialisation errors and exposes reload/low-graphics options after 25 seconds of unfinished startup. Low graphics changes graphics preferences only; it does not clear career, purchases or owner identity. Waiting remains possible. The timeout is a recovery option, not an imposed load deadline.

This fixes loading-screen handling; the exact cause on the reporting player's Mac was not captured. Startup still needs the approximately 34 MB standalone page and browser WebGL support.

Validation uses Chromium with external requests blocked: recovery UI without the engine, injected startup error, low-graphics selection retaining a storage sentinel, a deliberately invalid map exposing its error, and the real bundled map clearing the overlay and entering play. This extends earlier tests that checked worldReady without asserting the visible loading screen.
